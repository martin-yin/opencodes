# ESP32 USB 键鼠桥接

使用两块 ESP32-S3，通过 UART 转发 USB HID 数据：一块连接真实键鼠，另一块连接电脑并模拟 USB HID 设备。

> **测试范围：作者仅测试过罗技 G502，使用正常。其他键盘、鼠标、USB 接收器及其他设备均未测试，不保证兼容。**

## 工作原理

数据依次经过以下环节：

1. 真实 USB 键鼠连接 **Host 板**。
2. Host 板读取设备描述符和 HID 报告，通过 **3 Mbps UART** 发送给 Device 板。
3. **Device 板** 使用 TinyUSB 模拟 USB HID 设备，并将收到的报告发送给电脑。

两个固件分别位于：

| 工程目录 | 作用 | 原生 USB 连接对象 |
| --- | --- | --- |
| `kbme_host` | 读取原设备信息和 HID 数据 | 真实键鼠 |
| `kbme_device` | 模拟设备并转发 HID 数据 | 电脑 |

启动时，Host 板发送设备、配置、HID 报告及部分字符串描述符；Device 板据此启动 USB 模拟，并返回确认。随后开始转发按键、移动、滚轮等 HID 报告。

代码包含部分反向 `SET_REPORT` 转发，但不是完整的 USB 总线透传，不保证原设备的所有控制请求、厂商软件或附加功能可用。U 盘、摄像头、声卡等非 HID 设备不属于当前实现范围。

## 项目导航与采集工具

返回[项目总览](../README.md)。本项目的 `kbme_host` 和 `kbme_device` 是配套固件，默认 UART 速率一致；正常桥接不需要先用 Windows 工具采集描述符。

相邻 [usb_capture](../usb_capture/README.md) 提供 Windows 描述符采集工具和另一份 ESP32 Host 工程。它们与本项目有相似描述符帧格式，但串口参数、索引及缓冲区限制不同，不能默认互换。该 Host 工程不是 Windows 工具的描述符接收端。

## 硬件连接

建议使用两块带原生 USB 接口的 ESP32-S3 开发板。仓库依赖锁定文件的目标为 `esp32s3`。

- Host 板：原生 USB 接真实键鼠，需要适当的 USB Host 转接和 5V VBUS 供电。
- Device 板：原生 USB 接电脑。
- 烧录和查看日志可以使用开发板的独立 USB 转串口接口；该接口不能代替原生 USB 数据接口。

两块板之间按以下方式连接：

| Host 板引脚 | Device 板引脚 |
| --- | --- |
| GPIO17（TX） | GPIO18（RX） |
| GPIO18（RX） | GPIO17（TX） |
| GND | GND |

UART 参数为 **3000000 波特率、8 数据位、无校验、1 停止位、无硬件流控**。

使用 3.3V TTL 电平，不要接 RS-232 电平。高速串口建议使用短线。供电方式请按开发板电路确认，避免不同 USB 电源之间回灌。

## 编译与烧录

先安装并加载 ESP-IDF 环境。仓库依赖锁定文件记录的 ESP-IDF 版本为 **5.5.2**，建议优先使用该版本；其他版本未作兼容保证。

下载仓库：

```bash
git clone https://github.com/martin-yin/esp32_kbme.git
```

在仓库根目录打开终端，烧录 Host 板：

```bash
cd kbme_host
idf.py set-target esp32s3
idf.py -p <Host板串口> build flash monitor
```

另开终端，在仓库根目录烧录 Device 板：

```bash
cd kbme_device
idf.py set-target esp32s3
idf.py -p <Device板串口> build flash monitor
```

将尖括号占位符替换为实际串口名称；退出串口监视器使用 `Ctrl-]`。

## 使用步骤

1. 断电时接好两块板之间的 UART 和 GND。
2. 将 Device 板的原生 USB 接口连接电脑，并为两块板提供合适的供电。
3. 将罗技 G502 连接 Host 板的原生 USB 接口。
4. 等待 Host 板读取设备信息、Device 板完成 USB 枚举。
5. 在电脑上检查鼠标移动、按键和滚轮是否正常。

电脑端不需要本项目专用软件，按 USB HID 设备使用。

## 已知限制

- **仅测试过罗技 G502**。其他设备没有测试结果，不代表可以使用。
- Device 默认配置为 `CONFIG_TINYUSB_HID_COUNT=2`。接口数量更多的设备可能需要调整配置，调整后仍不保证兼容。
- 热插拔和更换设备处理不完善。出现异常时，可尝试两块板一起复位。
- USB 发送端未就绪时，当前实现会丢弃报告。不保证零丢包、固定延迟或实际达到 1000 Hz 回报率。
- 描述符复制不等于完整复现原设备，序列号、字符串、复杂复合接口及厂商扩展功能可能不完整或不兼容。
