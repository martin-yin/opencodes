# USB Device Info Capture

在 Windows 上读取 USB HID 设备的描述符，保存为二进制文件，并可通过串口发送给 ESP32 等接收端。

## 测试范围

- 作者仅测试过狼蛛键盘，其他品牌、型号和设备均未验证；不保证所有狼蛛键盘都能使用。
- 项目可能存在未知 Bug，不保证采集完整性或驱动恢复成功。

## 工作原理

工具通过 **PyUSB + libusb** 向设备发送 USB `GET_DESCRIPTOR` 控制请求，读取以下内容：

- **设备描述符**：VID、PID、USB 版本、厂商/产品/序列号字符串索引等。
- **配置描述符**：读取第一个配置的完整描述符树，包含接口、端点等信息。
- **字符串描述符**：先读取索引 0 的语言 ID 列表，再使用第一个语言 ID 尝试读取索引 1～10。
- **HID Report 描述符**：遍历当前配置中的 HID 接口，读取报告格式定义。

Windows 原有驱动可能阻止直接访问。点击“抓取”后，工具检查目标设备的接口驱动，必要时调用 `wdi-simple.exe` 将接口驱动切换为
**WinUSB**，等待设备重新枚举后读取数据。本次发生驱动切换时，抓取流程随后会尝试清理驱动、重新扫描设备。

采集结果保存在项目目录的 `usb_descriptors.bin`，布局为：

- 设备描述符，后接 `AA 55 00 01`。
- 配置描述符，后接 `AA 55 00 02`。
- 字符串描述符块，后接 `AA 55 00 03`。
- HID Report 描述符块，末尾不加分隔符。

字符串描述符按各自的长度字段连续存放；多个成功读取的 HID Report 描述符之间使用 `CC 33 00 01` 分隔。

“烧录”会将上述文件重新打包，以 `AA BB` 开头、`EE FF` 结尾，用 `0x01`～`0x04` 标记设备、配置、HID Report 和字符串描述符，再以以下参数发送：

- 波特率：`115200`。
- 每块最多：`64` 字节。
- 块间间隔：`50 ms`。

这里的“烧录”是发送描述符数据，**不是刷写 ESP32 固件**。接收端需要实现对应协议；本子项目不包含接收端固件，相邻 `kbme_device` 的默认配置也不能直接配套使用，见下节。

本工具读取的是描述符，不抓取按键、鼠标移动等实时 HID 报告或 USB 总线流量。

## 与其他工程的关系

本工具与同组的 [usb_hid_host](../usb_hid_host/README.md) 使用相同描述符串口帧结构，但两者都是描述符发送端；`usb_hid_host` 不接收本工具的数据，也不读取 `usb_descriptors.bin`。

相邻的 [ESP32 键鼠桥接](../../esp32_kbme/README.md) 中，`kbme_device` 有描述符接收和 TinyUSB 模拟逻辑，但默认 UART 为 3000000，本工具为 115200。还需核对 UART1 接线、索引映射与缓冲区限制，不能直接点击“烧录”就认为完成适配。完整关系及协议见[采集组说明](../README.md)；正常两板实时桥接不需要先运行本工具。

## 使用方法

### 1. 准备环境

在 Windows 上安装 Python 3，下载并解压本仓库。在项目目录打开终端，安装依赖：

```powershell
python -m pip install pyusb pyserial customtkinter
```

确保以下文件保留在项目根目录：

```text
libusb-1.0.dll
libwdi.dll
wdi-simple.exe
```

Python 与 DLL 的位数需要匹配。

由于工具会安装、移除驱动，请使用**管理员权限**打开终端，并始终从项目根目录运行：

```powershell
python gui.py
```

### 2. 抓取设备信息

1. 接入目标 USB HID 设备，点击“刷新设备”。
2. 在上方下拉框中根据产品名、VID/PID 选择目标设备。名称显示为 `<Need Hijack>` 时，可根据 VID/PID 识别。
3. 点击“抓取”，等待驱动检查、必要的 WinUSB 安装和描述符读取完成。
4. 检查日志中的各项读取结果，确认项目目录生成了 `usb_descriptors.bin`。

再次抓取会覆盖该文件，需要保留时请提前备份。

**驱动切换期间，目标设备的原有功能可能不可用。抓取键盘、鼠标时，请准备备用输入设备。**

自动清理和“清理驱动”按钮会搜索并尝试删除包含 `audit_` 或 `libusb-win32` 标识的驱动包，**并非只处理当前选择的设备**。使用前确认不会影响其他设备；驱动恢复不保证成功。

### 3. 查看抓取结果

在项目目录运行：

```powershell
python check.py
```

脚本读取 `usb_descriptors.bin`，在终端输出描述符解析结果，同时生成：

```text
usb_descriptors_解析报告_含ESP32代码.txt
```

报告包含设备信息、配置树信息、字符串内容、HID Report 原始十六进制数据以及分隔符的 C 数组定义。

### 4. 通过串口发送（可选）

1. 先完成抓取，确保 `usb_descriptors.bin` 存在且所需描述符读取成功。
2. 接入已实现接收协议的 ESP32 等设备，关闭其他占用该串口的程序。
3. 点击“刷新设备”，在下方下拉框选择接收端的 COM 端口。
4. 点击“烧录”，等待数据发送完成。

发送完成后，程序会持续监听串口，接收端反馈输出在启动程序的终端中；结束使用时关闭窗口。

也可以使用命令行发送：将 `main.py` 中的 `SERIAL_PORT` 改为实际端口，默认是 `COM9`，然后运行：

```powershell
python main.py
```

发送后持续监听反馈，按 `Ctrl+C` 停止并关闭串口。

当前文件格式未保存原始字符串索引和 HID 接口号，发送时按成功采集的数据顺序从 0 编号。若字符串索引存在空缺，或 HID 接口号不从 0 连续排列，接收端不能直接将该编号视为原设备索引。

采集或发送描述符不等于完整复现原设备功能。
